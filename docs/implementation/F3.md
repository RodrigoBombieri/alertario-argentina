## Corte implementado

- `InaStationCandidateParser` acepta explícitamente el catálogo observado `{ "estaciones": [...] }` y variantes sintéticas como array o `{ "rows": [...] }`; solo produce candidatos cuando estación y red tienen `public=true`. Son candidatos internos, no estaciones aprobadas para publicación.
- La identidad candidata de estación conserva ID de estación, ID y código de red, ID del propietario si existe, nombre, río y punto GeoJSON validado en orden longitud/latitud. Una geometría inválida o una identidad de red/estación duplicada invalida la página.
- `InaSeriesCandidateParser` conserva estación/red, variable, procedimiento, unidad y soporte temporal del catálogo `{ "rows": [...] }`. El soporte cero permite distinguir un candidato instantáneo de uno diario, pero **no demuestra cadencia de publicación**. `date_range` sin offset se conserva como texto, sin interpretarse como UTC.
- `GeoRefLocalityParser` conserva IDs textuales, provincia, categoría y centroide de cada localidad. Homónimos no se fusionan; una página con conteo inconsistente, ID duplicado o coordenadas inválidas se rechaza completa antes de sustituir un catálogo.
- `GeoRefSnapshotBuilder` solo construye un nuevo snapshot cuando todas las páginas son contiguas, tienen el mismo total y no repiten IDs. Una respuesta parcial o vacía no puede convertirse en reemplazo del catálogo anterior; el intercambio persistente queda para F4.
- `GeoRefLocalitySearch` consulta únicamente un snapshot completo en memoria. Busca nombres sin distinguir tildes ni mayúsculas, conserva la `ñ` como letra distinta, admite filtro por ID de provincia y limita resultados. Devuelve identidad, provincia y categoría por cada coincidencia: no fusiona homónimos ni asigna estaciones automáticamente.
- `InaStationCatalogClient` reconstruye las URLs de página bajo la base oficial, limita páginas y registros, ignora `next_page` del payload y rechaza páginas vacías, repetidas o inconclusas. `GeoRefCatalogClient` usa la base oficial v2, limita páginas, espera entre consultas y solo entrega un snapshot completo.
- `InaSeriesCatalogClient` consulta una estación por vez en el endpoint documentado, con una sola respuesta de hasta 1 MiB y menos de 300 filas. Rechaza otra estación, metadatos de truncamiento y esquemas desconocidos; un catálogo vacío es posible y no aprueba ninguna serie. La especificación local no documenta paginación de series, por lo que un resultado marcado como parcial no se sigue ni se publica.
- `InaObservationClient` pide una serie observada, instantánea y con unidad identificada dentro de una ventana UTC de hasta tres días, con precisión de segundos y final anterior a la ingesta. Acepta menos de 500 filas, rechaza respuestas marcadas como parciales y candidatos fuera del rango solicitado. Devuelve solamente los resultados internos `Candidate`, `Missing` o `Quarantined`; no calcula tendencia ni persiste.
- `InaSeriesApprovalGate` exige una entrada revisada y versionada por serie, con referencias de decisión de derechos e hidrología, tipo observado y coincidencia exacta de estación, red, variable, procedimiento, unidad y soporte temporal. El cliente de observaciones acepta solo el resultado de ese gate. No hay entradas aprobadas incluidas en el código; los tests usan decisiones ficticias. La clasificación no se infiere de `has_obs` ni del nombre de procedimiento, y soporte instantáneo no certifica cadencia.
- El transporte común exige HTTP 200 y JSON UTF-8, limita cada respuesta a 1 MiB y devuelve errores tipados para status, redirección, tipo, tamaño, schema, catálogo incompleto, red y timeout. Reintenta una vez ante 408/429/500/502/503/504 o error de red, con 20 s totales y `Retry-After` solo si no supera 5 s; errores semánticos y demás HTTP no se reintentan. La fábrica de clientes desactiva redirecciones automáticas y cookies; los tests usan handlers falsos. Los clientes INA/GeoRef se registran solo con sus flags opt-in y decisiones de derechos.
- `InaObservationNormalizer` acepta las dos envolturas de observaciones y entrega resultados `Candidate`, `Missing` o `Quarantined` por registro. No publica ni calcula tendencias.
- La normalización exige serie observada e instantánea identificada, `series_id` correspondiente y unidad de serie conocida. `unit_id:null` hereda esa unidad; un conflicto o unidad de serie desconocida queda en cuarentena.
- `timestart`, `timeend` y `timeupdate` se interpretan como instantes solo con offset explícito. El candidato conserva inicio/fin de observación, actualización de fuente e ingesta por separado. Fechas sin offset, intervalos invertidos y observaciones posteriores a la ingesta quedan en cuarentena.
- `valor:null` o `"null"` da `Missing`; un valor numérico cero es válido. Texto numérico no se interpreta como valor medido. Los IDs de observación usan 64 bits porque la evidencia F1 incluye valores mayores a 32 bits; IDs duplicados en un lote quedan en cuarentena.
- Las pruebas usan JSON sintético y verifican wrappers, unidad heredada, tiempos UTC, nulos, conflictos, homónimos y casos no publicables. La CI no llama a INA ni a GeoRef.
