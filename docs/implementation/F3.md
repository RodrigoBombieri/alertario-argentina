# F3 — normalización con fixtures sintéticas

**Estado al 2/10/2026:** F3 iniciada, no aceptada. El código de esta etapa no consulta organismos ni alimenta la API pública. Los [faltantes por motivos externos de F1](../research/f1/CLOSURE.md#faltantes-por-motivos-externos) siguen abiertos y el contrato F2 espera revisión de producto/datos.

## Corte implementado

- `InaStationCandidateParser` acepta explícitamente el catálogo observado `{ "estaciones": [...] }` y variantes sintéticas como array o `{ "rows": [...] }`; solo produce candidatos cuando estación y red tienen `public=true`. Son candidatos internos, no estaciones aprobadas para publicación.
- `GeoRefLocalityParser` conserva IDs textuales, provincia, categoría y centroide de cada localidad. Homónimos no se fusionan; una página con conteo inconsistente, ID duplicado o coordenadas inválidas se rechaza completa antes de sustituir un catálogo.
- `InaObservationNormalizer` acepta las dos envolturas de observaciones y entrega resultados `Candidate`, `Missing` o `Quarantined` por registro. No publica ni calcula tendencias.
- La normalización exige serie observada e instantánea identificada, `series_id` correspondiente y unidad de serie conocida. `unit_id:null` hereda esa unidad; un conflicto o unidad de serie desconocida queda en cuarentena.
- `timestart`, `timeend` y `timeupdate` se interpretan como instantes solo con offset explícito. El candidato conserva inicio/fin de observación, actualización de fuente e ingesta por separado. Fechas sin offset, intervalos invertidos y observaciones posteriores a la ingesta quedan en cuarentena.
- `valor:null` o `"null"` da `Missing`; un valor numérico cero es válido. Texto numérico no se interpreta como valor medido. IDs duplicados en un lote quedan en cuarentena.
- Las pruebas usan JSON sintético y verifican wrappers, unidad heredada, tiempos UTC, nulos, conflictos, homónimos y casos no publicables. La CI no llama a INA ni a GeoRef.

## Lo que falta para aceptar F3

| Trabajo | Estado / desbloqueo |
|---|---|
| Metadatos completos de estación, red, serie, procedimiento y geometría; importación paginada/atómica GeoRef | Trabajo de implementación y pruebas pendiente; el parser GeoRef inicial ya conserva IDs y homónimos |
| Canal SMN CAP autorizado, completo y estable; ciclo Alert/Update/Cancel | **Faltante por motivos externos EXT-02**; obtener contrato y ejemplos institucionales antes del adapter operativo |
| Publicación de series INA, parámetros de frescura, datum/umbrales y asociación localidad/estación | **Faltantes por motivos externos EXT-01/03/04**; ver [vía de resolución](../research/f1/CLOSURE.md#faltantes-por-motivos-externos) |
| Adapter HTTP con límites, paginación reconstruida, errores tipados y detección de drift; pruebas de fallos | Trabajo de implementación pendiente; no conectar a red real sin presupuesto y permiso |
| Pruebas de normalización y contrato ante `unit_id:null`, unidad conflictiva, fechas ambiguas, nulos y cambios de wrapper | Primer corte verificado; ampliar con los casos anteriores y fixtures autorizadas |

Los candidatos del parser no se registran como fuente configurada en el host API ni como allowlist. El entorno de producción sigue devolviendo `dataNotConfigured`.
