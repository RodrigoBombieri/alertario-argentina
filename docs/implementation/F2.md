# F2 — contrato propio y backend sintético

**Estado al 2/10/2026:** F2 no aceptada. Hay un corte técnico implementado para revisar el contrato HTTP, pero F1 sigue pendiente por motivos externos. Historia principal: US-04. El contrato mínimo es provisional hasta revisión de producto/datos.

## Alcance de este corte

- Solución .NET 10 con `Core`, `Application`, `Infrastructure`, `Api` y `Worker`. `Application` define el puerto `IPublicDataReader`; `Infrastructure` aporta una implementación sintética y otra sin datos configurados.
- API v1 con búsqueda de localidades, estaciones, asociación localidad/estación, ficha de estación, summary, avisos y fuentes. El [OpenAPI generado](../../contracts/openapi/v1.json) fija **el subconjunto implementado ahora**; las demás rutas de [OWN-API](../design/OWN-API.md) son diseño futuro.
- Fixture exclusivamente ficticia: “Localidad de ejemplo”, “Estación de ejemplo” y “Río de ejemplo”. Todas las respuestas útiles indican `synthetic=true`. No contiene datos ni identificadores INA, SMN o GeoRef.
- Summary con altura sintética identificada como tal, caudal `null` y motivo, cinco ventanas 1/3/6/12/24 h sin delta por insuficiencia, umbrales y avisos vacíos, `noticeCoverage.status=notConfigured`. `generatedAt`, `observedAt`, `sourceUpdatedAt` e `ingestedAt` son campos distintos.
- El modo sintético solo se registra en `Development` con `SyntheticData:Enabled=true`. Sin otro modo, en `Production` las rutas de datos responden 503 `application/problem+json` con `code=dataNotConfigured`; `/health/ready` también responde 503. D14/D15 agregaron un modo de arranque **explícito** con `ColdStart:Enabled=true`: búsqueda y ficha sirven una estación ficticia con 14 días horarios simulados, el mapa queda vacío, `/v1/status` marca `collecting` y `officialDataAvailable=false`, y `/health/ready` indica `collecting=true`. Todas las respuestas de la muestra conservan `synthetic=true`; la cobertura de avisos es `notConfigured`. No consulta fuentes reales. `/health/live` comprueba solo el proceso. El worker arranca sin ingesta ni conexiones externas.
- OpenAPI 3.1 generado por ASP.NET Core, servido solo en desarrollo y guardado sin URL de servidor local. Las pruebas comparan el documento guardado con el de la API en ejecución.
- Una prueba HTTP inyecta dos formas sintéticas del catálogo INA (`estaciones` observada y `rows` alternativa) a través del puerto de lectura y verifica la misma respuesta pública. El parser interno descarta estaciones o redes con `public=false`; no habilita consumo ni publicación de datos INA reales.

Los bloqueos de fuentes, medición y especialistas de F1 son **faltantes por motivos externos** con resolución documentada en su acta. La revisión del contrato requiere una decisión de producto/datos; no se presume aprobada por el avance técnico.

## Ejecutar y verificar

Desde la raíz del repositorio:

```powershell
dotnet restore backend/AlertaRio.sln --locked-mode
dotnet format backend/AlertaRio.sln --verify-no-changes --no-restore
dotnet test backend/AlertaRio.sln --no-restore
$env:ASPNETCORE_ENVIRONMENT = 'Development'
dotnet run --project backend/src/AlertaRio.Api --urls http://127.0.0.1:5096
```

En otra terminal: `GET http://127.0.0.1:5096/v1/stations/station-demo/summary` y `GET http://127.0.0.1:5096/openapi/v1.json`. Para actualizar el documento guardado tras una modificación de rutas/DTO, guardar la respuesta de OpenAPI en `contracts/openapi/v1.json` y correr nuevamente las pruebas de contrato. La CI ejecuta restore bloqueado, formato y pruebas sin llamadas a organismos.

Dependencias fijadas: SDK 10.0.401; `Microsoft.AspNetCore.OpenApi` 10.0.10 y `Microsoft.OpenApi` 2.7.5, esta última fijada explícitamente para evitar la versión transitiva vulnerable. Se revisará el avance de parche al actualizar dependencias.
