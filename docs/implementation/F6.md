# F6 — Flutter MVP

**Estado al 3/10/2026:** iniciada, no aceptada. Existe un proyecto Flutter Android/iOS y un flujo local de consulta. Solo usa la API propia; todavía no puede mostrar datos oficiales ni un gráfico temporal reciente.

## Corte implementado

- `apps/mobile` contiene la app Flutter con Riverpod para inyección, Dio para la API propia y SQLite (`sqflite`) para favoritos y la última ficha válida de cada estación. `API_BASE_URL` se pasa por `--dart-define`; en release exige HTTPS. No accede a INA, SMN ni GeoRef desde el teléfono.
- La pantalla de búsqueda distingue localidad y provincia, requiere selección explícita de estación y muestra el río informado. No usa cuenta ni GPS. La ficha presenta altura, caudal, hora absoluta de medición, fuente, cinco ventanas, estado de calidad y cobertura de avisos sin convertir `null` en cero o una lista vacía de avisos en “sin alertas”.
- Los favoritos se guardan localmente y se pueden quitar repetidamente. Si falla la red o la API devuelve 503, la ficha muestra la copia SQLite con un aviso visible de desconexión y la hora absoluta original. Un 403/404 elimina la copia de esa estación para no seguir mostrando datos cuyo acceso fue retirado. La caché valida versión de esquema y descarta JSON incompatible.
- La pestaña Explorar usa la lista de estaciones por bbox de F7 como alternativa mientras no haya proveedor de tiles aprobado. No calcula un estado agregado para el área.
- El análisis estático y pruebas Flutter cubren favoritos vacíos, recuperación offline, revocación de una ficha y persistencia SQLite tras cerrar y reabrir la base. Falta probar en dispositivos y completar el flujo de datos vivos.

| Builds y plataformas | El proyecto Android/iOS se generó y `flutter analyze`/`flutter test` pasan. El build APK está bloqueado por `PKIX path building failed` al descargar Android Gradle Plugin de Google Maven/Maven Central. Es un bloqueo TLS del entorno: incorporar la CA confiable al truststore del JDK/Gradle o corregir el proxy y repetir `flutter build apk --debug`; luego probar Android en dispositivo. iOS requiere macOS y smoke propio |
| Identidad de publicación | El proyecto generado conserva identificadores `com.example` y assets de launcher de prueba; definir identificador propio y material gráfico antes de distribuir |

Para desarrollo local: iniciar el backend sintético en `Development` con `SyntheticData__Enabled=true`, y ejecutar `flutter run --dart-define=API_BASE_URL=http://10.0.2.2:<puerto>` desde `apps/mobile` en emulador Android. La excepción de tráfico HTTP solo existe en el manifest Android de debug. La versión de release requiere HTTPS. No se incluye un servidor público configurado por defecto.
