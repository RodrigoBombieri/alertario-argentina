# F4 — base de datos e ingesta

**Estado al 3/10/2026:** F4 iniciada, no aceptada. Las migraciones 0001/0002 y sus smokes pasaron en PostgreSQL 17/PostGIS 3.5 local. No hay ingesta en Worker ni conexión de la API a la base.

## Corte implementado

- La migración [0001_initial.sql](../../infrastructure/db/migrations/0001_initial.sql) crea fuentes, estaciones, series, localidades, asociaciones curadas, mediciones, revisiones, `latest`, cuarentena, corridas y checkpoints con lease. Usa IDs externos calificados por fuente/red, tiempos `timestamptz`, geometrías PostGIS e índices espaciales y temporales.
- `approved=false` y `permission_status=pending` son los estados iniciales. Una serie aprobada exige tipo observado, soporte instantáneo, unidad, versión de aprobación y referencias de derechos e hidrología. No se insertan series ni fuentes reales.
- La clave natural `(serie, inicio, fin)` impide duplicar una medición; las revisiones tienen número propio. El reloj de observación, el de actualización fuente y el de ingesta permanecen separados. `latest` referencia una medición de la misma serie.
- `MeasurementReconciler` decide en memoria entre insertar, ignorar un replay idéntico, revisar una corrección posterior o poner en cuarentena un conflicto sin orden temporal. Un nuevo reloj de ingesta no convierte un replay idéntico en observación nueva.
- [0002_ingestion_writer.sql](../../infrastructure/db/migrations/0002_ingestion_writer.sql) implementa un escritor transaccional invocable por lote. `claim_ingestion_lease` concede o renueva lease por stream; `commit_ingestion_batch` verifica dueño y vigencia, serializa series afectadas, resuelve inserción/replay/revisión/cuarentena, recompone `series_latest` y avanza cursor/cobertura en la misma transacción. Una excepción revierte todo el lote. Todavía falta un adaptador Worker que lo invoque y convierta la salida del normalizador al JSON de entrada.
- [Smoke 0002](../../infrastructure/db/tests/0002_ingestion_writer.sql) verificó lease competido por dos dueños, replay sin duplicados, revisión con historial y versión de `latest`, corrección antigua en cuarentena, protección de checkpoint y rollback de lote inválido. Usa fuente/serie sintéticas y revierte los fixtures al final. La prueba de competencia es secuencial; aún falta concurrencia real entre sesiones y recuperación de proceso caído.
- La vista interna `publishable_measurements` exige a la vez serie aprobada, fuente con permiso aprobado, tipo observado y calidad aceptada. Si se revoca el permiso de la fuente, deja de devolver esas filas; todavía no la consume la API.
- El catálogo GeoRef se carga como snapshot versionado. `activate_catalog_snapshot` comprueba el conteo antes de cambiar el puntero activo en una transacción; un snapshot incompleto no reemplaza al anterior. El smoke real verificó ambas rutas con datos ficticios.
- [Compose local](../../infrastructure/compose.yaml) usa `postgis/postgis:17-3.5` solo para desarrollo, con puerto ligado a `127.0.0.1:5433` y credencial local fija. La imagen y la ruta del volumen siguen la [documentación del proyecto PostGIS Docker](https://github.com/postgis/docker-postgis/blob/master/README.md). No es configuración de producción.
- El [smoke SQL](../../infrastructure/db/tests/0001_smoke.sql) usa datos ficticios dentro de una transacción que termina en `ROLLBACK`. Comprobó PostGIS, activación de snapshot completo, rechazo del parcial, geometría, aprobación con evidencia, revocación de permiso y clave natural de medición. Se verificó `schema_migrations=0001_initial` y cero fuentes ficticias remanentes.

## Pendiente para aceptar F4

| Trabajo | Estado / desbloqueo |
|---|---|
| Ejecutar migración y probar restricciones/PostGIS sobre PostgreSQL real | 0001/0002 y smokes pasaron el 3/10/2026 en Docker local; faltan ejecución versionada de migraciones, concurrencia entre sesiones y ensayo de recuperación tras caída |
| Ingesta transaccional idempotente, revisión y `latest` | Función DB y replay/corrección/rollback sintéticos probados; falta integración Worker/normalizador y lectura persistida desde la API |
| Lease, reconciliación y cuarentena durables | Funciones DB y prueba secuencial presentes; faltan renovación operacional, recuperación tras caída y competencia real entre workers |
| Publicación de datos oficiales | Bloqueada por las puertas externas de [F1](../research/f1/CLOSURE.md#faltantes-por-motivos-externos) y aceptación de F3; no es necesaria para probar F4 con datos sintéticos |

Para una base **nueva** con Docker Desktop en ejecución, `docker-compose -f infrastructure/compose.yaml up -d db` inicializa ambas migraciones. Para un volumen existente con 0001, aplicar `docker-compose -f infrastructure/compose.yaml exec -T db psql -U alertario_dev -d alertario_dev -v ON_ERROR_STOP=1 -f /opt/alertario/migrations/0002_ingestion_writer.sql`, luego ejecutar los smokes `/opt/alertario/tests/0001_smoke.sql` y `/opt/alertario/tests/0002_ingestion_writer.sql` del mismo modo. Verificar antes `schema_migrations`; no reaplicar 0002. La carpeta `/docker-entrypoint-initdb.d` se procesa solo al crear el volumen; aún falta ejecutor versionado para despliegue. Este corte no declara F4 terminada.
