# F4 — base de datos e ingesta

**Estado al 3/10/2026:** F4 iniciada, no aceptada. Se creó un esquema local para datos sintéticos; no se ejecutó todavía contra PostgreSQL/PostGIS porque el daemon de Docker no está disponible en este equipo. No hay ingesta en Worker ni conexión de la API a la base.

## Corte implementado

- La migración [0001_initial.sql](../../infrastructure/db/migrations/0001_initial.sql) crea fuentes, estaciones, series, localidades, asociaciones curadas, mediciones, revisiones, `latest`, cuarentena, corridas y checkpoints con lease. Usa IDs externos calificados por fuente/red, tiempos `timestamptz`, geometrías PostGIS e índices espaciales y temporales.
- `approved=false` y `permission_status=pending` son los estados iniciales. Una serie aprobada exige tipo observado, soporte instantáneo, unidad, versión de aprobación y referencias de derechos e hidrología. No se insertan series ni fuentes reales.
- La clave natural `(serie, inicio, fin)` impide duplicar una medición; las revisiones tienen número propio. El reloj de observación, el de actualización fuente y el de ingesta permanecen separados. `latest` referencia una medición de la misma serie.
- La vista interna `publishable_measurements` exige a la vez serie aprobada, fuente con permiso aprobado, tipo observado y calidad aceptada. Si se revoca el permiso de la fuente, deja de devolver esas filas; todavía no la consume la API.
- El catálogo GeoRef se carga como snapshot versionado. `activate_catalog_snapshot` comprueba el conteo antes de cambiar el puntero activo en una transacción; un snapshot incompleto no reemplaza al anterior. La función y las restricciones aún requieren prueba en una base real.
- [Compose local](../../infrastructure/compose.yaml) usa `postgis/postgis:17-3.5` solo para desarrollo, con puerto ligado a `127.0.0.1:5433` y credencial local fija. La imagen y la ruta del volumen siguen la [documentación del proyecto PostGIS Docker](https://github.com/postgis/docker-postgis/blob/master/README.md). No es configuración de producción.
- El [smoke SQL](../../infrastructure/db/tests/0001_smoke.sql) usa datos ficticios dentro de una transacción que termina en `ROLLBACK`. Comprueba PostGIS, activación de snapshot completo, rechazo del parcial, geometría, aprobación con evidencia, revocación de permiso y clave natural de medición; está preparado pero no ejecutado.

Para una base **nueva** con Docker Desktop en ejecución, `docker-compose -f infrastructure/compose.yaml up -d db` inicializa la migración; luego `docker-compose -f infrastructure/compose.yaml exec -T db psql -U alertario_dev -d alertario_dev -v ON_ERROR_STOP=1 -f /opt/alertario/0001_smoke.sql` ejecuta el smoke. Este equipo dispone del ejecutable `docker-compose`, pero no del subcomando `docker compose`. La carpeta `/docker-entrypoint-initdb.d` se procesa solo al crear el volumen; futuras migraciones requerirán un ejecutor versionado. Este corte no declara F4 terminada.
